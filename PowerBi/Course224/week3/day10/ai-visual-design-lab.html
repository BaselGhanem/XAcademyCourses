Prompt Configurationكل خطوة بتحدّث الـPrompt تلقائيا

01 — اشرح للـAI شو بدك تحلل

أهم خطوة. لا تبدأ بالحركة قبل ما تحدد السؤال والبيانات الصحيحة

أمثلة جاهزة حسب مجال المتدرب
كيف تجيب أسماء الحقول الصحيحة؟ افتح Data / Fields Pane داخل Power BI، وانسخ اسم الـMeasure كما هو (مثال [Total Revenue]) واسم العمود مع اسم الجدول (مثال DimProduct[Category]). أسماء الـMeasures تحت أي جدول ما بتغير طريقة استخدامها داخل Measure.
اكتب أسماء الـMeasures، وإذا كتبت Total Revenue لحالها رح نجهزها بالـPrompt على شكل [Total Revenue]. راجع أسماءها من Power BI
للبطاقات الفردية ممكن تتركه فاضي

03 — الألوان والهوية والحركة

04 — الحدود التقنية وجودة الناتج

هاي الخطوة بتمنع كثير من المشاكل الشائعة: أرقام غلط، Scrollbar، كود غير مدعوم، أو Measures مختلقة

✓DATA FIRST / ANIMATION SECOND
الرسم لازم يظهر كاملا حتى لو الحركة ما اشتغلت. لا تخفي الأعمدة أو الخطوط بـscaleX(0) أو opacity:0 في الحالة الأساسية، وافحص أكبر قيمة وأصغر قيمة قبل اعتماد الكود.

لما يكون مفعل، رح يطلب من الـAI نسخة ثابتة كاملة وسليمة أولاً، وبعدها يضيف تأثير بصري غير مؤثر على طول الأعمدة أو ظهور القيم. الخيار الأفضل للعرض المباشر.

عندك رسم عاجبك؟ استخدمه كمرجع

الصورة بتظل على جهازك. بعد نسخ الـPrompt أرفقها بنفسك للـAI؛ الموقع ما برفعها لأي سيرفر

مهم: التصميم التفاعلي داخل HTML مش نفس Power BI Native Cross-filtering. اطلب من الـAI يشرح شو مدعوم فعليا في إصدارك، ويعطيك بديل باستخدام Native Visuals أو Buttons عند الحاجة. لا تفترض أن JavaScript أو ملف SVG قابل للضغط رح يعمل بكل البيئات

THE NON-NEGOTIABLES
أهم 3 قواعد قبل استخدام أي كود




01 / CORRECT DATA
لا تعتمد على شكل جميل ورقم غلط
استخدم الـMeasures الحقيقية، اطلب احترام Filter Context وراجع نفس الرقم بVisual أصلية قبل اعتماد نسخة HTML


02 / POWER BI LIMITS
مش كل Hover يعني تفاعل مع التقرير
Hover داخل HTML ممكن يكون بصري فقط. اختبر إصدار HTML Content الموجود عندك، ولا تفترض دعم JavaScript أو Native Selection


03 / PERFORMANCE
رسم سريع وواضح أحسن من 10 حركات
حدد Top N والحد الأقصى للعناصر، وتجنب كود ثقيل ورسومات كثيرة، وخلي الحركة خفيفة وقابلة للإيقاف
