Power Query | تنظيف بيانات تقييم الاداء

اليوم الثاني: نتعلم Transform عمليا، ونشتغل على نظام Objective / KPI المعتمد في شغل مريم

01 — نفهم سجل التقييم قبل ما ننظفه

نزلي الملف الرئيسي (CSV) من Get Data → Text/CSV → Transform Data

المصدر يحتوي 10120 سجل، منها 120 نسخة مكررة مطابقة، فيتبقى 10000 AssessmentID فريد

كل صف = علامة KPI واحدة لشخص يتم تقييمه، من جهة تقييم محددة، في دورة تقييم محددة. نفس الموظف رح يظهر بعدة صفوف وهذا طبيعي، مش تكرار لازم ينحذف

الـObjective له وزن ثابت، والـKPIs تحته ما إلها أوزان منفصلة. الـObjective Score لاحقا = متوسط KPI Scores التابعة له، ثم نطبق وزن الـObjective. اليوم لا نكتب DAX

02 — نراجع Data Types وApplied Steps

  1. افتحي Power Query Editor وراجعي Query Settings → Applied Steps
  2. خلي AssessmentID وSubjectID وEvaluatorID وKPIID نوعها Text، حتى لو الاسم فيه ارقام
  3. غيّري ObjectiveWeight وKPI_Score الى Decimal Number، وEvaluationDate الى Date
  4. اذا Power Query صنع Changed Type تلقائيا، راجعيه ولا تخلي الاخطاء تختفي بدون فهم سببها
الدرجة الصحيحة من 0 الى 100. تحويل Score لنوع رقمي ما يكفي: القيمة 125 رقم لكنها غير منطقية، فبدنا Quality Check مستقل

03 — Trim / Clean / Replace Values

  1. حددي Department وEvaluationType وObjectiveName وKPIName ← Transform → Format → Trim ثم Clean
  2. وحدي Manger الى Manager، وSelf Assessment الى Self، وUpward Feedback الى Upward باستخدام Replace Values بالمطابقة الكاملة
  3. وحدي HR الى Human Resources فقط عندما تعني نفس القسم في بيانات التدريب
  4. القسم الفارغ (حتى لو كان فيه مسافات فقط) نخليه Unassigned كفئة بيانات ناقصة، بدون اختراع قسم للموظف

04 — Null / Errors / Invalid Scores

  1. حوّلي KPI_Score الى Decimal Number ثم Replace Errors → null لدرجات مثل N/A
  2. حددي القيم خارج مجال 0–100 (مثل 125) ووثقيها ثم استبدليها بـ null، وليس بصفر. ممكن استخدام Conditional Column لتحديد Out of Range
  3. حوّلي EvaluationDate الى Date؛ القيم مثل 2026-13-40 ستنتج Errors: استبدلي الخطأ بـ null مع توثيق الحالات
  4. اتركي درجات Pending فارغة: عدم وصول التقييم لا يعني صفر اداء
لا تستخدمي Remove Errors على الجدول كله؛ خطأ بدرجة أو بتاريخ لا يبرر حذف سجل تقييم كامل

05 — Duplicate vs Repeated KPI

  1. رتبي البيانات حسب AssessmentID وشوفي اذا النسخ المتكررة مطابقة تماما. اذا كان في تعارض لازم نحلله، مش ناخذ صف بشكل عشوائي
  2. في ملف التدريب هذا فقط النسخ المكررة مطابقة، فحددي AssessmentID ثم Home → Remove Rows → Remove Duplicates
  3. النتيجة 10000 صف، مش 800 صف: الموظف الواحد إله عدة KPIs واتجاهات تقييم
  4. راجعي Applied Steps ثم Close & Apply وسمّي الجدول PerformanceKPI_Clean

06 — نثبت الفرق بالـVisuals

  1. Card بعدد Count لـAssessmentID → 10000 تقييم KPI
  2. Card بعدد Distinct Count لـSubjectID → 820 شخصا تم تقييمهم (800 موظف و20 مدير)
  3. Table تعرض EvaluationType / Department / Status، وSlicer لنوع التقييم
  4. عند اختيار Manager لازم عدد سجلات KPI يساوي 4800؛ Self = 4800؛ Upward = 400
  5. اعتمديها كاختبار عملي للفلاتر من Day 01، بدون Measures لسا
لاحظي ان 820 تمثل الاشخاص المقيمين في الملف، وليس 820 موظفا رسميا، والـUpward لا يختلط مع تقييم الاداء الوظيفي العام
