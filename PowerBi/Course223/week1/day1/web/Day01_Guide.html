هدف الجلسة

رح نقدر ربط مصدر، شرح رحلة ETL، وبناء تقرير يجيب: كم موظفا؟ كيف يتوزعون حسب المنشاة والفئة؟ وكيف تتغير النتيجة مع الفلتر؟

بنبلش بـ Excel والتقرير، وبعدين بنجرب باقي المصادر سوا

01 — قبل البداية

ننزل Power BI Desktop من Microsoft على جهاز Windows. فكي حزمة اليوم في مجلد ثابت. نفتح Excel ونراجع اول عشرة صفوف، ثم اجيبي: ما الصف؟ ما الشهر؟ هل المعرف يتكرر؟

02 — الاتصال بملف Excel

من Home نختار Get Data ثم Excel Workbook، او ابحثي عن الموصل في واجهة Get Data الجديدة. نختار Workforce_Starting_Snapshot.xlsx، ثم جدول WorkforceSnapshot فقط في Navigator، وبعدها Transform Data. لا نختار ورقة البيانات وجدولها معا

03 — التحويل في Power Query

نسمي الاستعلام Workforce. نحدد EmployeeID كـ Text وSnapshotDate كـ Date وFTE كـ Decimal Number، وبقية الحقول كـ Text. نراجع Applied Steps: المصدر ثم التنقل ثم النوع. هذا تحويل بسيط؛ التنظيف المتقدم في اليوم الثاني. نختار Close & Apply

04 — واجهات البرنامج

Report لبناء الرسوم، Table/Data لمراجعة الصفوف، Model لمراجعة الجداول والعلاقات. تسمية واجهة الجدول قد تختلف حسب النسخة. نراجع Home: Get Data وTransform Data وRefresh، ثم Save

05 — بطاقة عدد الموظفين

اضيفي Card ونسحب Workforce[EmployeeID]. من تجميع الحقل نختار Count (Distinct)، وليس Sum ولا عدد المنشات. نسمي البطاقة عدد الموظفين ونضبط عرض الوحدات لتظهر 168 كاملة. لا نحتاج كتابة DAX اليوم

06 — التوزيع حسب الفئة

نضيف Bar chart افقي: Cadre للفئات، وEmployeeID للقيم مع Count (Distinct). نفعل Data labels ونرتب من الاكبر للاصغر. للرسم الثاني نستخدم Doughnut chart: FacilityName في Legend، وعد الموظفين في Values

07 — الفلتر واختبار التفاعل

اضيفي Slicer للحقل FacilityName. نختار North Training Hospital: يجب ان يتغير العدد الى 48. نختار Nursing داخل الرسم: العدد 24 عند فلترة التقاطع. امسحي اختيار الرسم والفلتر لعودة 168. طلع معك رقم مختلف؟ نراجع Edit interactions

08 — حفظ التقرير

نسمي الصفحة Workforce Overview، واضيفي عنوانا يذكر September 2026. نحفظ باسم Day01_Workforce.pbix. اغلقي الملف ونفتحه للتحقق من الحفظ. هذا الملف بننشئه اثناء التطبيق؛ لا توجد نسخة PBIX جاهزة ضمن الحزمة

09 — استكشاف المصادر مع المدرب

للمقارنة فقط: Get Data ثم Text/CSV لملف Facility_Master.csv، وText/CSV لملف Facility_Demo.txt مع فاصل Tab، وPDF لملف Facility_Demo.pdf واختيار جدول المنشات في Navigator. يمكن ان يختلف اسم الجدول المستخرج؛ نقارن 4 صفوف. لمصدر Web نفتح صفحة Facility_Directory.html العامة ونستخدم رابطها عبر Web مع Anonymous. لا تستخدمي رابط GitHub tree او blob كجدول بيانات. اذا لم تكن الصفحة منشورة نستخدم CSV المحلي. لا تربطي هذه المصادر بالتقرير اليوم

10 — لمحة اضافية حسب الوقت

اعرضي CSV البديل للموظفين في ملف Power BI جديد فقط، ليظهر انه يحمل نفس 168 موظفا. اظهري Mobile layout كعرض موجه اذا بقي وقت. لا يعد النشر او تسجيل الدخول للخدمة شرطا لحفظ التقرير المحلي

المفاهيم بامثلة التطبيق

ETL

Extract: قراءة الملف، Transform: ضبط النوع، Load: تحميل جدول Workforce الى النموذج

Excel vs CSV

Excel يحتوي اوراقا وجداول وتنسيقا؛ CSV جدول نصي بفاصل، بلا اوراق او تنسيق

Power Query

مكان تجهيز البيانات بخطوات يعاد تنفيذها عند التحديث، منفصل عن صفحة التقرير

Count vs Distinct Count

العد الفريد يمنع عد المعرف نفسه مرتين. البيانات اليوم فريدة، لكن اختيار التجميع الصحيح اساس الايام القادمة

Card / Chart / Slicer

البطاقة تجيب كم، الرسم يوضح التوزيع، والفلتر يحدد الجزء الذي نريد مراجعته

Headcount vs FTE

موظفان بنصف دوام = موظفان في العدد و1 في FTE. اليوم نتعلم العدد، وقياسات FTE التفصيلية لاحقا

Snapshot

اللقطة تمثل وضعا في تاريخ واحد؛ لا تجمعي عدد سبتمبر مع عدد اكتوبر كعدد موظفين حالي

Report vs Dashboard

اليوم نبني صفحة تقرير داخل Desktop؛ الداشبورد بمعناه التقني في الخدمة موضوع لاحق

حل المشكلات

  • ظهور مجموع خاطئ: نتاكد من Count (Distinct) للحقل EmployeeID
  • تضاعف العدد: نتاكد انك لم تجمعي Excel وCSV لنفس الموظفين
  • الفلتر لا يؤثر: نستخدم حقول Workforce نفسها ونراجع تفاعل العناصر
  • فشل Refresh بعد نقل الملف: اعيدي تحديد مكان المصدر من Data source settings
  • تشوه CSV: نختار UTF-8 والفاصل Comma
